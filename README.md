# ice-cream v0.6.4 使用说明

ice-cream 是一个 Zotero 9 及以上版本的全文、多论文 AI 阅读插件。除实际调用模型 API 外，文献解析、分块和本地检索均在 Zotero 内完成。插件使用面向未来版本的宽兼容范围，避免 Zotero 主版本升级时仅因版本号范围而被自动禁用；若未来 Zotero API 发生破坏性变化，仍可能需要代码适配。

## 已实现

- Zotero 中显示 **ice-cream** 浮动入口。
- Tools 菜单中增加 **ice-cream**。
- 点击入口后打开独立桌面窗口，可移出 Zotero 主窗口并自由缩放；下次打开会恢复位置和大小。
- 独立窗口右上角有图钉按钮：默认灰色且不置顶，点击后变为黄色并始终保持在其他窗口上方，再次点击恢复普通窗口层级。置顶时仍可自由移动和改变大小。
- 读取 Zotero 已索引 PDF 的逐页全文，而不再只读取题名、摘要和日期。
- 以 `[S1:p2]`、`[S2:A2:p5]` 格式保留论文、附件和 PDF 页码引用。
- 一次固定最多 12 篇选中文献、PDF 附件或 note，组成多论文研究工作区。多次点击 `Use Selection` 会把新论文追加到已固定工作区，保持原有 `[Sx]` 顺序并自动去重，不再覆盖前一次选择。
- `Use Selection` 只为下一次提问上传原始 PDF；请求成功后自动解除上传状态。后续问题会从同一批 Zotero 来源中按问题重新检索相关全文页，但不会重复上传 PDF；询问图、表或公式时，单篇论文默认发送 6 个相关页面，两篇发送 8 页，总上限 12 页。
- 对只能接收图片的模型，首次提问优先保证视觉信息完整：短论文尽可能发送全部页面，上限 48 页；原始 PDF 被接口拒绝后的图片回退上限为 32 页。
- 相关页采用混合定位：精确匹配 `Table 3`、`Table III`、`Fig. 9`、`式 (40)` 等编号，优先识别真实题注和章节标题，再以中英文概念扩展进行本地语义重排，并围绕最强命中页补充相邻页。
- 每段新对话都可独立选择 `Full text` 和 `PDF`；`Settings` 中的同名选项作为新对话的默认值。
- 每次后续提问都会携带当前对话中完整的用户/助手文本历史，不再丢失上文。
- 对话文本会自动保存到 Zotero 数据目录下的 `ice-cream/conversations.json`，并根据首个问题自动命名；顶部使用插件内菜单切换历史对话，避免 Zotero 原生下拉菜单无响应。
- 历史对话下拉菜单的每个条目右侧都有“圆圈叉号”按钮，可从本地记录中永久删除该条目。删除当前条目后会自动打开最近的剩余对话；若无剩余记录，则只创建一个新的空对话。
- `New Chat` 会保留当前历史并开始新对话；`Clear` 会从本地历史文件永久删除当前对话、清空固定论文并开始一个空白对话。
- 上传原始 PDF 时会先为每篇选中文献保留一个附件，再轮流补充额外附件，并把每个文件明确标记为 `[S1]`、`[S2]` 等来源。
- 若存储型 PDF 仅存在于 Zotero 云端，插件会在调用模型前通过 Zotero 同步服务按需下载；缺失的外部链接文件会明确提示而不会静默忽略。
- 显式点击 `Use Selection` 后的下一次提问会按问题相关度选择全文片段，并为每篇选中文献保留基本上下文份额。
- 可对当前 Zotero library 的题名、摘要、作者、标签、DOI、期刊等元数据建立内存索引。
- 支持通过 `Search Library` 在本地检索元数据；普通 AI 提问不会自动把其他论文的检索结果发给模型。
- 原生支持 DeepSeek、OpenAI、Claude、Qwen，并支持自定义 OpenAI-compatible API。
- Model 使用下拉菜单显示各 Provider 的较新模型；`Refresh` 可读取当前 endpoint 实际开放的模型列表，也可输入自定义模型 ID。
- AI 回复按 Markdown 排版，并使用 KaTeX 显示行内公式和块公式；表格、列表和代码块均有独立样式。
- 每次请求都会附加严格的 Markdown/LaTeX 公式格式与 KaTeX 可编译性要求，避免模型输出缺少、重复反斜杠或照抄 OCR 公式碎片。
- 显示前会修复模型偶发输出的双重转义 LaTeX 命令，同时保留矩阵、分段公式中的正常换行。
- 对数学区域内常见的缺失反斜杠命令（如 `frac{...}`、`pi`、`beta`）会做保守修复。
- 鼠标悬停在已排版公式上可查看归一化后的 LaTeX 源码。
- 若公式仍无法通过 KaTeX 校验，插件会自动进行一次不重复上传 PDF 的纯格式修复请求。
- 独立窗口会先初始化为标准模式文档，再加载内置 KaTeX 渲染器和样式，确保分式、上下标和希腊字母按数学结构显示。
- 普通公式会保持为一个数学块并根据窗口宽度自动缩放，只有极端超长公式才启用横向滚动。表格单元格中的公式会单独适配单元格宽度，不再为每个公式生成滑条；只有整张表格确实超宽时才显示一个共享滑条。
- 每次调用会实时显示当前 Provider、模型、处理阶段和累计等待时间。
- 回复完成后显示总用时；`Stop` 可真正取消当前 API 请求，`Edit Question` 可恢复最近问题并修改后重发。
- Model 使用插件内可搜索下拉菜单，避免 Zotero 原生下拉菜单无响应，并支持大量 endpoint 模型滚动筛选。
- 用户点击 `Use Selection` 且当前对话勾选 `PDF` 时附带首轮视觉证据；后续询问图、表、公式、曲线或坐标时会自动附带相关页面。支持原生 PDF 的接口首轮直接上传，不支持的 Qwen 模型会在本地渲染页面后发送。
- Qwen 3.7 系列使用官方支持的图片与文本输入，不再发送会触发 400 的 `file` 内容块；若其他端点意外拒绝 PDF，插件也会自动渲染相关页面并携带页码标签重试。
- 支持把最后一次 AI 回复保存为 Zotero note。

## 安装

1. 确认使用 Zotero 9 或更高版本。
2. 打开 Zotero。
3. 进入 `Tools -> Plugins`。
4. 点击齿轮按钮，选择 `Install Plugin From File`。
5. 选择 `ice-cream-0.6.4.xpi`。
6. 如 Zotero 提示，重启 Zotero。

## 配置

打开 ice-cream 窗口，点击 `Settings`：

- Provider：`DeepSeek`、`OpenAI`、`Claude`、`Qwen` 或 `Custom`
- Endpoint：切换 Provider 时带出独立默认值，也可改为兼容接口
- Model：从较新模型下拉列表选择；点击 `Refresh` 获取该 endpoint 对当前密钥开放的模型；选择 `Custom model ID...` 可手工输入
- API Key：你的 provider API key
- Max results：点击 `Search Library` 时显示的本地检索结果数量
- Temperature：模型温度
- Context characters：全文片段的最大字符预算，默认 180000
- Full text：新对话中 `Selection payload` 的默认全文选项
- Attach PDF：新对话中 `Selection payload` 的默认 PDF 选项

不同 Provider 的 endpoint、model 和 API key 分开保存。API key 当前存储在本机 Zotero preferences 中，尚未接入系统钥匙串；不要共享包含 Zotero profile 的备份。

## 使用

1. 在 Zotero 文献列表中选中一篇或多篇文献；在 PDF Reader 中也可使用当前论文。
2. 点击右下角 `ice-cream`。
3. 在窗口顶部选择本次对话的 `Full text`、`PDF` 选项。
4. 点击 `Use Selection` 固定当前选择并武装下一问。状态栏会显示论文数、PDF 页数和已提取字符数。
5. 点击 `Index Library` 可预热当前 library 的元数据索引。
6. 输入问题：
   - “总结这篇论文的主要贡献”
   - “我的库里有哪些论文和这个主题相关？”
   - “比较选中三篇论文的假设、算法复杂度和实验结论”
   - “解释第 4 页图 2，并指出结论依据”
7. 点击 `Ask AI`，或按 `Cmd/Ctrl + Enter`。
8. 后续问题会自动带上当前文本对话历史，并从本地 Zotero 论文中重新检索最多约 60,000 个相关字符；不会再次上传完整 PDF。询问图、表或公式时，会按“精确编号 -> 题注/章节标题 -> 语义重排 -> 前后各两页扩展”的顺序补充页面图像；单篇默认 6 页，两篇 8 页，三篇及以上总上限 12 页。
9. 如需保存结果，点击 `Save Note`。

窗口顶部的对话下拉菜单可切换已保存会话。每个条目右侧的圆圈叉号用于永久删除该条记录；删除非当前条目不会打断正在查看的对话。`New Chat` 保留旧会话并开始新会话；`Clear` 会永久删除当前会话，不可从插件历史中恢复。历史文件保存用户/助手文本和用于重新定位论文的 Zotero item ID，不保存 PDF、全文提取结果或 API key。

提问后可随时点击 `Stop` 取消当前网络请求。点击 `Edit Question` 会把最近一次问题恢复到输入框并全选；如果模型仍在处理，会先自动终止请求。

模型调用期间，对话中会保留一张实时状态卡。卡片显示当前模型、正在执行的阶段和 `mm:ss` 累计时间；这里显示的是请求处理与等待耗时，不会展示或伪造模型的私有思维链。

回复结束后，状态卡和回复底部都会显示 `Total time mm:ss`。

## Save Note 保存位置

- 当前选中论文或其 PDF 附件时：结果保存在该论文下面的子笔记 `ice-cream Note` 中。展开论文左侧的小箭头即可看到。
- 没有选中可归属的论文时：结果作为独立笔记保存在当前 Zotero library 的中间条目列表中。
- `Save Note` 保存到 Zotero 数据库，不会在磁盘上另外生成 Markdown 或 Word 文件。

## Markdown 与公式

- 标题、粗体、列表、引用、表格、链接和代码块会按 Markdown 结构显示。
- `$E=mc^2$`、`\(...\)` 显示为行内公式；`$$...$$`、`\[...\]` 显示为居中块公式。
- Markdown HTML 在显示前经过标签和链接白名单清理，模型回复不能注入脚本。
- 块公式优先缩小到当前窗口宽度，避免不必要的换行和横向滑条；只有缩放后仍无法清晰容纳的极长公式才允许横向滚动。

## PDF、图片与表格

- 文字型 PDF：正文、公式文本、图题和可复制表格会进入逐页全文上下文。
- 点击 `Use Selection` 且当前会话勾选 `PDF` 后，插件会在下一问附带 PDF 视觉证据。支持原生 PDF 的接口最多附带 8 个 PDF，单个不超过 64 MB，总计不超过 120 MB；选择多篇论文时优先保证每篇一个 PDF。
- 原始 PDF 是图片、图表、公式和表格版式的主要证据；提取文字只负责页面检索和引用定位。
- OpenAI 使用 Responses `input_file`，Claude 使用 document block，DeepSeek 使用顶层 `file_data`。Qwen 3.7 Plus 等只支持图片、文本和视频输入的模型会把相关 PDF 页面转为 `image_url`；支持原生 PDF 的 Qwen 3.8 Max/27B 会优先使用嵌套 `file` block 直接上传完整 PDF，仅在服务端实际拒绝后回退页面图片。
- 当端点只接受图片时，首次提问会在 48 页上限内尽可能覆盖每个物理页面；超过上限时先为每篇论文保留相关页，再按问题相关度和页面覆盖范围补足。每张图前附带 `[Sx:py]` 引用标签。
- 若没有可用 PDF，插件会尝试发送 Zotero Reader 当前页图像。
- 扫描 PDF 即使提取字符数为 0，也会在接口允许时作为原始 PDF 上传，或为 Qwen 3.7 等视觉模型渲染成页面图像。

## 多论文选择

- `Use Selection` 会把当时的选择追加到固定工作区，仅切换 Zotero 条目不会悄悄改变上下文。
- 再次选择其他条目并点击 `Use Selection` 会继续添加来源，已存在的条目会自动去重。该工作区只发送给紧随其后的下一问。
- `New Chat` 会保存当前会话并开始新工作区；`Clear` 会从本地永久删除当前会话，同时清空最后回复与所有 pinned sources。清空后再点击 `Use Selection` 只会载入当前选中的条目。
- 同一条目的多个附件会标记为 `A1`、`A2`；引用示例 `[S2:A2:p5]` 表示第 2 篇论文的第 2 个附件第 5 页。
- 上下文过长时，插件先为每篇论文分配份额，再按问题相关度补充页面，减少长论文淹没短论文的情况。

## 当前限制

- 尚未实现扫描 PDF 的本地 OCR、PDF bbox 级跳转、Reader 原生侧栏、标注写回和 note diff。
- 多论文工作区最多 12 个来源；视觉 PDF 最多 8 个、单个不超过 64 MB 且总计不超过 120 MB。
- 本地 library 搜索仍是元数据索引，全文问答针对当前固定工作区。

## 后续开发建议

优先级建议：

1. 持久化全文向量索引和跨库 RAG。
2. 扫描 PDF OCR、图片单独提取和表格结构化。
3. PDF 句子/bbox 引用点击跳转。
4. Zotero Reader 原生侧栏与标注写回。
5. Notes diff 编辑与文献综述模板。
